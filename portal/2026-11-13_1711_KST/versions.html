How versions work

  1. Every substantial change receives a NEW, timestamped filename including Korea Standard Time.
  2. The previous manuscript, model, results and journal page remain where they are.
  3. Each new step explains what changed, why, and which prior files it used.
  4. Git tracks exact content hashes and chronological commits.
  5. The new preservation workflow checks the frozen 89 original files and flags modifications or deletions in tracked content.

What the timestamp means

Historical times on step pages are the GitHub commit publication times, converted from UTC to KST. These are not asserted to be the original creation time of an idea or data download. This portal edition was initiated on 13 November 2026 at approximately 17:11 KST.

What is protected—and what is not?

The append-only checks help catch accidental overwrites. GitHub history can show prior versions, but they are not guaranteed permanent: repository owners can delete the project or change protections, and a local machine can be lost. Keep a separate private backup, especially for source data that cannot be shared publicly.

How a future revision will be named

2026-11-14_0930_KST__STEP_12__validation_protocol__v01.md

A later manuscript could be 2026-11-xx_HHMM_KST__STEP_15__manuscript_v03.md. Earlier papers remain independent and accessible.
